# 영수증 → TripPay 가져오기 프롬프트

아무 AI(Claude·ChatGPT·제미나이)에 **영수증 사진들과 함께 아래 프롬프트를 통째로 붙여넣으면**
TripPay 가져오기 JSON이 나온다. 받은 JSON을 `.json` 파일로 저장 → AirDrop → 앱 랜딩의
"여행 데이터 가져오기"로 열면 끝.

- **새 여행 생성**: 프롬프트만 붙여넣기.
- **기존 여행에 추가**: 앱에서 내보낸 JSON을 사진과 함께 주고 "이 여행에 지출을 추가해 줘"라고 지시.
  (같은 여행 id로 가져오면 기존 여행이 갱신된다)
- 2026-08-05 실증: 실제 영수증 20장 → 확인 질문 1개, 수정 0건.
- **앱 탑재 (2026-08-06)**: "AI로 영수증 입력" 화면(`screens/ImportAIScreen.js`)이 이 프롬프트를 품고,
  결과는 **클립보드 붙여넣기**로 받는다 — 파일·AirDrop·서버 없이 복사 두 번이 전부.
  프롬프트 사본은 `receiptPrompt.js`와 워커 `/upload` 페이지에도 있다. **고치면 셋을 같이 고칠 것.**

## 프롬프트 (여기서부터 복사)

첨부한 영수증 사진들을 읽어 아래 형식의 JSON 하나로 만들어 줘.
여행 경비 앱(TripPay)의 가져오기 파일이라 형식을 정확히 지켜야 해.
출력은 JSON 코드블록 하나만. 인사말·설명·요약·표는 쓰지 마.

```json
{
  "app": "TripPay",
  "version": 1,
  "trip": {
    "id": "trip_<여행을 짧게 영문으로>",
    "name": "<국가명> 여행",
    "startDate": "YYYY-MM-DD",
    "endDate": "YYYY-MM-DD",
    "country": { "flag": "🇯🇵", "name": "일본", "code": "JPY", "sym": "¥", "r100": true, "exRate": "930" },
    "countries": [
      { "flag": "🇯🇵", "name": "일본", "code": "JPY", "sym": "¥", "r100": true, "exRate": "930" }
    ],
    "members": ["총무"],
    "note": "영수증 자동입력"
  },
  "deposits": [], "charges": [], "exchanges": [], "atms": [], "refunds": [],
  "expenses": [
    { "id": 1, "name": "<항목명>", "amt": 12345.67, "cur": "JPY", "pay": "현금", "date": "MM-DD", "note": "<메모>" }
  ],
  "krwExps": [
    { "id": 1, "name": "<항목명>", "amt": 12345, "pay": "현금", "date": "MM-DD", "note": "<메모>" }
  ]
}
```

규칙:

1. **지출 1건 = 영수증 1장.** `amt`는 영수증의 최종 합계(현지통화). 세금·할인이 반영된 실제 지불액을 쓴다.
   **영수증에 찍힌 그대로 쓴다 — 소수점이 있으면 반올림하지 말고 그대로.** (예: `10.92`)
   여러 명 몫이 한 장에 찍혀 있어도 1인분 금액이 아니라 합계를 쓴다.
2. `date`는 `MM-DD` 형식. `id`는 1부터 순번.
3. `pay`는 `"현금"` 또는 `"트래블카드"` 둘 중 하나만. 영수증에 현금 표시가 있으면 현금, 카드 결제면 트래블카드.
   영수증만으로는 선불카드인지 신용카드인지 알 수 없으니 카드 종류는 묻지 마.
   신용카드로 낸 건은 내가 앱에서 직접 바꾼다. 카드 끝 4자리가 보이면 `note`에 남겨 줘.
4. `name`은 한국어로 짧게(가게명 또는 용도). 상세(지점·인원·구성)는 `note`에.
5. **원화(KRW) 지출은 `expenses`가 아니라 `krwExps`에** 넣는다. `pay`는 여기에도 3번 규칙대로 넣어 줘
   (원화는 언제나 계좌에서 빠지고 `pay`는 분류용이지만, 내역에서 결제수단으로 걸러 보는 데 쓴다).
6. **여러 나라 영수증을 한 번에 줘도 된다.** 외화 지출마다 `cur`에 그 통화 코드를 적고,
   `countries`에는 거쳐 간 나라를 **모두** 담는다(`country`는 그중 첫 나라를 그대로 둔다).
   예: 스위스+이탈리아 여행이면 `countries`에 두 나라를 넣고 지출마다 `"cur": "CHF"` / `"cur": "EUR"` 를 적는다.
   앱이 통화별로 알아서 나눠 넣는다.
7. `country`·`countries`는 여행 국가에 맞게. 자주 쓰는 값:
   | 국가 | code | sym | r100 | exRate |
   |---|---|---|---|---|
   | 일본 | JPY | ¥ | true | 930 |
   | 캐나다 | CAD | C$ | false | 980 |
   | 베트남 | VND | ₫ | true | 5.5 |
   | 태국 | THB | ฿ | false | 40 |
   | 미국 | USD | $ | false | 1350 |
   | 유럽 | EUR | € | false | 1500 |
8. `trip`의 `name`은 `"<국가명> 여행"`, `startDate`·`endDate`는 영수증 날짜 중 가장 이른 날과 가장 늦은 날로 채운다.
   여행 정보는 앱에서 고치니 묻지 마.
9. 금액이나 날짜를 못 읽겠으면 추측하지 말고 **그 영수증만 빼고** 나머지로 JSON을 만들어.
   뺀 영수증은 JSON 앞에 한 줄로 알려줘. 그 외에는 아무것도 묻지 마.
10. JSON은 코드블록 하나로만.

## 참고

- 이 파일 형식의 단일 출처는 `transfer.js`(`buildTripJson`)다. 스키마가 바뀌면 이 문서도 같이 고칠 것.
- 회비·충전·환전은 영수증에 없는 정보라 항상 비워진다 — 가져온 뒤 앱에서 입력.
- 참여자·분담은 전원 균등으로 들어간다 — 필요한 지출만 앱 내역에서 조정.
- v1.2 "코드로 가져오기"(QR)가 생기면 파일 저장·AirDrop 단계가 사라진다. 그때 업로더 페이지(`/upload`)가
  이 프롬프트의 출력을 그대로 받도록 유지한다.
