# 영수증 → TripPay 가져오기 프롬프트

아무 AI(Claude·ChatGPT·제미나이)에 **영수증 사진들과 함께 아래 프롬프트를 통째로 붙여넣으면**
TripPay 가져오기 JSON이 나온다. 받은 JSON을 `.json` 파일로 저장 → AirDrop → 앱 랜딩의
"여행 데이터 가져오기"로 열면 끝.

- **새 여행 생성**: 프롬프트만 붙여넣기.
- **기존 여행에 추가**: 앱에서 내보낸 JSON을 사진과 함께 주고 "이 여행에 지출을 추가해 줘"라고 지시.
  (같은 여행 id로 가져오면 기존 여행이 갱신된다)
- 2026-08-05 실증: 실제 영수증 20장 → 확인 질문 1개, 수정 0건.
- **앱에는 탑재하지 않는다** (2026-08-06 결정): "복사 → 다른 앱 → 파일 저장 → AirDrop → 가져오기"는
  일반 사용자에게 내놓기엔 번거로워 v5.1에서 뺐다. 이 문서는 개발자·코워크용 워크플로우로 유지하고,
  사용자용은 v1.2 "링크로 가져오기"(탭 한 번)로 제공한다.

## 프롬프트 (여기서부터 복사)

첨부한 영수증 사진들을 읽어 아래 형식의 JSON 하나로 만들어 줘.
여행 경비 앱(TripPay)의 가져오기 파일이라 형식을 정확히 지켜야 해.

```json
{
  "app": "TripPay",
  "version": 1,
  "trip": {
    "id": "trip_<여행을 짧게 영문으로>",
    "name": "<여행 이름>",
    "startDate": "YYYY-MM-DD",
    "endDate": "YYYY-MM-DD",
    "country": { "flag": "🇯🇵", "name": "일본", "code": "JPY", "sym": "¥", "r100": true, "exRate": "930" },
    "members": ["<참석자1>", "<참석자2>"],
    "note": "영수증 자동입력"
  },
  "deposits": [], "charges": [], "exchanges": [], "atms": [], "refunds": [],
  "expenses": [
    { "id": 1, "name": "<항목명>", "amt": 12345, "pay": "현금", "date": "MM-DD", "note": "<메모>" }
  ],
  "krwExps": []
}
```

규칙:

1. **지출 1건 = 영수증 1장.** `amt`는 영수증의 최종 합계(정수, 현지통화). 세금·할인이 반영된 실제 지불액을 쓴다.
2. `date`는 `MM-DD` 형식. `id`는 1부터 순번.
3. `pay`는 `"현금"` 또는 `"트레블월렛"`(선불 외화카드) 둘 중 하나만. 영수증에 현금 표시가 있으면 현금,
   카드 결제로 보이면 나에게 어느 카드였는지 물어봐.
4. `name`은 한국어로 짧게(가게명 또는 용도). 상세(지점·인원·구성)는 `note`에.
5. **원화(KRW) 지출은 `expenses`가 아니라 `krwExps`에** 넣는다(`pay` 필드 없음). 통화를 섞지 마.
6. `country`는 여행 국가에 맞게. 자주 쓰는 값:
   | 국가 | code | sym | r100 | exRate |
   |---|---|---|---|---|
   | 일본 | JPY | ¥ | true | 930 |
   | 베트남 | VND | ₫ | true | 5.5 |
   | 태국 | THB | ฿ | false | 40 |
   | 미국 | USD | $ | false | 1350 |
   | 유럽 | EUR | € | false | 1500 |
7. 참석자 이름은 영수증에 보이면 그대로, 없으면 내가 알려줄 때까지 비워두고 물어봐.
8. 금액·날짜가 흐릿하거나 1인분/합계가 애매한 영수증은 **추측하지 말고 질문**해.
9. 끝에 확인용 요약을 붙여 줘: 건수, 통화별 합계, 날짜 범위, 애매했던 항목.
10. JSON은 코드블록 하나로만. 파일 생성이 가능하면 `.json` 파일로도 만들어 줘.

## 참고

- 이 파일 형식의 단일 출처는 `transfer.js`(`buildTripJson`)다. 스키마가 바뀌면 이 문서도 같이 고칠 것.
- 회비·충전·환전은 영수증에 없는 정보라 항상 비워진다 — 가져온 뒤 앱에서 입력.
- 참여자·분담은 전원 균등으로 들어간다 — 필요한 지출만 앱 내역에서 조정.
- v1.2 "코드로 가져오기"(QR)가 생기면 파일 저장·AirDrop 단계가 사라진다. 그때 업로더 페이지(`/upload`)가
  이 프롬프트의 출력을 그대로 받도록 유지한다.
